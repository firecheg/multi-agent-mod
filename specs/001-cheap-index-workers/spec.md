# Feature Specification: Graphify и небольшие исполнители чтения

Created: 2026-09-08. Author: Codex. Scope approved by user: Graphify CLI,
Haiku and Codex Luna selected by task, Spotify-style bulk-read routing.

## User Scenarios & Testing

1. P1: основной агент задаёт ограниченные вопросы по проекту. Harness получает
   выборку существующего Graphify-индекса, передаёт её и выбранные исходники
   Haiku (summary) или Luna (code), возвращает короткие ответы и расход.
   Проверка: два реальных CLI-вызова; JSON результата не содержит исходников.
2. P1: полное чтение большого файла блокируется hook; небольшой диапазон разрешён.
   Проверка: Read и простые Bash/PowerShell-команды; Codex требует native trust.
3. P2: до шести независимых вопросов выполняются максимум тремя работниками;
   общий ответ ограничен, одинаковые задачи не вызывают повторную модель.
   Ошибка одного исполнителя не вызывает повтор или дорогую замену.

## Requirements

- Индексы Graphify хранятся в общем проектном скилле или по явному пути реестра.
- Нельзя отдавать graph.json целиком основной модели. Индекс имеет источник,
  hash и метаданные снимка. Устаревший граф не является доказательством текущего кода.
- Сильная модель читает нужные исходные диапазоны для правок, архитектуры и
  сложной диагностики. Массовое чтение для ориентации делегируется.
- CLI исполнителей используют существующую авторизацию; credentials не копируются.
- Нет автоматической переиндексации, API-покупок, циклов генерации и code-writer.
  Это адаптация bulk-reader, не полная копия Portal/Shunt.
- Shell hook ограничивает поддержанные формы команд, не является песочницей
  против произвольных программ. Незагруженный/недоверенный hook не объявляется работающим.

## Success Criteria

Проверены границы файлов, выбор моделей, максимальная параллельность, кэш,
ошибки, ограничения ответа и hook; оба CLI отвечают на маленькую реальную задачу.
