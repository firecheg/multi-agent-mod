# Память и совместная работа

Ищи память только если прошлое решение действительно помогает; ограничивай область текущим проектом и явно глобальными заметками. Записывай один устойчивый факт, которого нет в коде или документации; не сохраняй секреты и очевидное. Противоречие исправляй в существующей заметке.

Для MCP указывай абсолютный `project`, для CLI — текущий каталог; не расширяй область заметки. Хранилище задаёт `AGENT_HARNESS_MEMORY`. Загружай skill только по триггеру: `multi-agent` — для координации, `speckit` — для существенной многоэтапной функции, если он установлен. Если установлена общая обвязка agent-harness, общий каталог skills — `~/.agent-harness/skills`, реестр подключений — `~/.agent-harness/connections.json`, а `shared-harness` — для её обслуживания.

При делегировании передавай узкий контекст и не допускай параллельных изменений одних файлов. Независимое ревью выполняет другой автор/модель по фактическим файлам; разные псевдонимы одного автора независимость не создают. Для новой функции с несколькими этапами или агентами используй спецификацию проекта.

В reusable harness сохраняй нейтральность провайдеров и не включай личное состояние, credentials, transcripts, память или skills в Git.
