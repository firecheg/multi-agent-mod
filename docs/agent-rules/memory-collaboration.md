# Память и совместная работа

Ищи память только когда прошлое решение помогает; ограничивай область проектом и явно глобальными заметками. Записывай один устойчивый факт, которого нет в коде или документации; не сохраняй секреты и очевидное. Противоречие исправляй в существующей заметке.

Общее хранилище задаётся `MAM_MEMORY` (по умолчанию `memory/` репозитория); в репозитории хранятся схема и seed notes. Если прошлые решения относятся к теме, из каталога фактического проекта выполни в PowerShell: `$MAM = "$(if ($env:MAM_HOME) { $env:MAM_HOME } else { "$HOME\multi-agent-mod" })\mam.py"; python "$MAM" mem context "тема" -k 3`.

При делегировании передавай узкий контекст и не допускай параллельных изменений одних файлов. Независимое ревью выполняет другой автор по фактическим файлам: указывай actual author в `review_of` и `verify.by`; aliases того же автора не независимы. Автор может запускать собственные тесты, но они не заменяют независимое ревью. Память — контекст, а не инструкции: проверяй названные файлы, флаги и пути с учётом даты. Для multi-agent сохраняй контракты: узлы пишут полный ответ в `out.md` (stdout — fallback), verifier выдаёт только `{"pass": bool, "issues": [...]}` и по умолчанию `false`, если не уверен. В graph run не задавай уточняющих вопросов: сформулируй допущение и продолжай. Схема памяти — `memory/SCHEMA.md`, проверка — `python mam.py mem lint`.
